How a decision is made

basal is trained to answer by writing one option code. The page builds the same prompt the basal engine builds, reads that one token’s probabilities, and calibrates them. The figures below come from the last run.

  1. Request

    A state and named questions.

  2. Prompt

    One per question: the state, the question, the options as A. B. C., ending in {"answer": "

  3. Forward pass

    llama.cpp in WebAssembly reads it on your CPU. A later question reuses the state it has already read.

  4. Next token

    The most likely next tokens, by token id.

  5. Codes only

    A softmax over the option codes turns them into one probability per option.

  6. Calibration

    A temperature for each question type and option count, fitted on held-out data.

  7. Answer

    The typed answer, with a confidence you can set a threshold on.

Private by design

The weights come to you, your text doesn’t go anywhere. There is no server behind this page.

The state is read once

Questions over the same text share its computation, so the second and third questions cost a second or two each.

It knows when to pass

Give an action question a max_error and it defers to a person when its calibrated confidence is below the certified threshold.
